Privacy

ABlock processes site data in your browser. This page explains what data the extension needs, where it is stored and when network requests occur.

Permissions and site access

Required permissions are listed in the extension's manifest:

declarativeNetRequest
Blocks ads, trackers and dangerous URLs using built-in rules. An exception rule is created for sites where you turn protection off.
scripting
Inserts scripts and CSS to remove ads, hide banners and gather information for the report: technologies, loading, markup and other page metrics.
activeTab
Accesses the current tab when you open the extension window to read its address and get page data for the report.
storage
Stores settings, exceptions, notes and statistics in the browser. Details are below.
Access to specific sites
Video platforms and social networks: YouTube, VK, OK and others. Scripts and styles remove ads from players, feeds and pages on these sites.

For the report, ABlock reads page cookies accessible to JavaScript in the browser (excluding HttpOnly). It uses clues such as PHPSESSID and wordpress_ to identify site technologies. For the security check, it finds up to three cookie names that appear to relate to signing in. This is an inference based on the name. The extension does not store cookie values or transmit them anywhere.

Optional permissions

When you enable extended mode, ABlock requests webRequest and access to all URLs (<all_urls>). This lets it obtain the server IP and selected response headers, count image formats and track blocked requests. Access to all sites is also needed to hide cookie banners and empty ad spaces and to increase the buffer of information about page resources that have loaded.

You can turn extended mode off using the button at the bottom of the expanded score panel. The extension then removes both permissions. Turning the mode off does not, by itself, delete stored statistics.

browsingData is requested separately the first time you use the “Clear site data” trash button. After confirmation, ABlock deletes cookies, cache, Cache Storage, file systems, IndexedDB, localStorage, service workers and WebSQL for the current site and reloads the tab without cache. For storage, HTTP and HTTPS addresses with and without www. are included; the browser deletes cookies for the domain. This may sign you out of the site.

What is stored in the browser

The extension uses chrome.storage.local for the data below. The code does not use chrome.storage.sync: the extension does not send this data to browser sync.

Protection settings
aBlockStorage — whether protection is enabled (status); aBlockSettings — the setting for hiding cookie banners (cookies); aBlockAllowed — the list of domains where protection is off.
Language and appearance
aBlockLang — the selected window language; aBlockTheme — the selected theme; aBlockDark — a dark-theme flag used for the counter colours on the extension icon.
Notes
aBlockNotes — your texts, associated with the site name without the leading www..
Overall statistics
aBlockStats — three numbers: blocked request count (requests), estimated data saved (bytes) and the time counting began (since). Savings are estimated using the average request size for each type. These overall statistics do not contain a list of visited sites.
Reminder timestamps
aBlockInstalled — the installation time or, for existing users, the first update with this feature. aBlockRated and aBlockAsked — when you clicked a button or dismissed a request to rate the extension or support the project. These track when requests were shown, not confirmation of a rating or payment.

Temporary data

In chrome.storage.session, extended mode stores aBlockTabs: for each tab, the site name, server IP, selected response headers, image format counts, estimated data saved and counts of blocked URLs. For the latter, the domain and up to 40 characters of the path are recorded, without query parameters; there are at most 300 such entries per tab. Tab data is deleted when the tab closes and replaced when a response for a new main page arrives. Session storage lasts until the browser closes.

aBlockClear in the same storage is a temporary instruction to clear a site: the tab ID, its full URL and the time of the click. It is needed in case the extension window closes while permission is being requested. If permission is granted, the instruction is removed and carried out only if less than two minutes have passed; if permission is denied, it is removed.

How to change or delete data

You can change protection, language and theme settings in the extension window. To remove a site from the exceptions, turn protection on for it. To delete a note, open it, clear the text and press Enter to save.

There is currently no single button in the interface to delete all settings and statistics. The “Clear site data” trash button deletes the site's own data, not ABlock settings. To delete all extension data, uninstall ABlock from your browser's extensions page: chrome://extensions in Chrome or browser://extensions in Yandex Browser.

Requests made by the extension

Opening the ABlock window starts a page check. It requests three files from the current site: /robots.txt, /llms.txt and /.well-known/security.txt. Their URLs are constructed from the current site's address. They provide information about rules for search and AI bots and the presence of a security contact. Requests omit credentials (credentials: omit), have a two-second timeout and follow server redirects, including to a different address.

All other fetch calls read files from the installed extension: translations, company and hosting directories, ruleset descriptions, its own and third-party cosmetic filters and, when creating a report image, local images and the background. These are not downloaded from project servers. The server IP comes from browser events; hosting is identified using a database inside the extension.

The VK script intercepts the page's fetch: HEAD ad-blocker checks to four advertising and counter URLs receive an artificial successful response; other calls are passed to the site's original function. This handles the site's requests; it does not send extension data.

There are no other independent network requests in the extension code: it does not contact DoH, whois, third-party APIs or analytics, and it does not send settings, notes or statistics to a server. There are no XMLHttpRequest calls. Filter lists and the hosting database are bundled with the extension.

Links and “Share”

Chrome Web Store, Boosty, Telegram and GitHub open when you click them. These are visits to external sites, rather than background transfers of ABlock data.

The “Share” menu can open a service you choose. The selection depends on the interface language; in English it includes, for example, Telegram, X, Reddit and Hacker News. The link contains the extension's store URL and the report text or extension description, depending on the action and service selected. Some services receive only the link. A report may contain the checked site's name, score, server information and findings from the check.

You can also copy the report image or text, save the image as a file or send it through the system “Share” menu if your browser supports it. You choose the recipient. The respective external services handle your visits and the material you send.
