# Changelog проекта

Пиши по-русски для пользователей и операторов; источник поведения — код и diff,
а не только сообщения коммитов или целевая концепция. Не выдумывай изменения.

## Границы и доказательства

- Уточни целевой коммит или ветку из запроса; иначе используй текущий HEAD.
- Определи предыдущую выпущенную версию по существующему CHANGELOG и тегам,
  достижимым из цели. При неоднозначности запроси границу у пользователя.
- Для «Не выпущено» изучи diff от подтверждённого релизного тега до цели,
  журнал и окружающий код; учитывай отмены по итоговому состоянию.
- Если релизов и тегов ещё нет, не объявляй всю историю невыпущенной:
  запроси базовый коммит или явно согласованный охват первого выпуска.
- При отсутствии нужных объектов, неполной истории или конфликте границ сообщи
  об этом и запроси уточнение; не делай fetch без необходимости и разрешения.
- Для незафиксированных изменений включай рабочее дерево только по запросу;
  в ответе укажи выбранный диапазон и ограничения проверки.
- Сверяй реализацию с конфигурацией и документацией; целевые планы записывай
  как реализованные только после подтверждения кодом в выбранной цели.

## Что включать

- Видимые изменения публичных контрактов, API, CLI, интерфейсов, форматов входных
  и выходных данных, параметров, заголовков и кодов ошибок.
- Изменения конфигурации, окружения, зависимостей и инфраструктуры, если они
  меняют поведение, развёртывание или действия оператора.
- Зависимости и рефакторинг — только при заметном эффекте или необходимых
  действиях. Внутренние инструкции, тесты и форматирование сами по себе опускай.
- Каждая запись объясняет результат; несовместимость и действие пользователя или
  оператора укажи явно. Объединяй изменения одного поведения, не дублируй их.
- Не раскрывай секреты, ключи доступа, токены и внутренние детали реализации.

## Публичность и ссылки

**Категорически запрещены ссылки на локальные и игнорируемые файлы и пути**:
`.agents/local/`, `.agents/tasks/`, `.agents/workers/`, `.env`, другие пути
из правил ignore и абсолютные пути хоста. Проверяй весь итоговый файл, включая
Markdown, HTML, ссылки-сноски и изображения. Не вставляй секреты или данные
локальной конфигурации. API-маршрут — не путь к локальному файлу.
- При необходимости ссылайся только на отслеживаемый файл относительно корня,
  предварительно проверив его через `git ls-files`; либо на внешнюю задачу.
- Подтверждённый ID задачи в трекере ставь в конце записи:
  `([#123](https://deviz.kaiten.ru/123))`. Не выдумывай ID и не считай
  произвольный номер задачи номером трекера без подтверждения контекста.
- Ссылки сравнения необязательны: используй фактический веб-адрес текущего
  репозитория и проверенный формат хостинга, если оба известны. Не угадывай
  адрес по SSH origin и не оставляй неразрешённые ссылки-сноски.

## Обновление

1. Если корневого `CHANGELOG.md` нет, прочитай `templates/changelog.md`
   относительно каталога скилла и создай файл по шаблону. Если файл есть,
   сохрани его шапку и историю; не заменяй его шаблоном.
2. Используй Keep a Changelog: `## [Не выпущено]`, затем выпуски от новых к
   старым. Категории только непустые, по порядку: «Добавлено», «Изменено»,
   «Исправлено», «Удалено», «Безопасность». Записи начинай с сути и заверши точкой.
3. Обнови «Не выпущено» по установленному диапазону; сохрани подтверждённые
   записи вне охвата, не удаляй их при неполном исследовании. Если корректно
   объединить их нельзя, сообщи о границе и запроси уточнение.
4. При явном запросе закрыть релиз используй согласованную версию и дату
   существующего тега, проверь соответствие содержания его коммиту. При ещё
   не созданном теге не утверждай, что релиз состоялся; запроси данные и способ
   подготовки. Закрой раздел версией и создай пустой «Не выпущено» сверху.
5. Сохраняй все прошлые выпуски. Не удаляй и не архивируй их автоматически.
   Ссылки сравнения, если достоверны, обнови по фактическим границам.
6. Проверь порядок, даты, ссылки и отсутствие запрещённых путей и секретов;
   выполни `git diff --check`. Сообщи диапазон, результат и ограничения.
   Коммит, создание тега и отправку выполняй только по явному поручению.
