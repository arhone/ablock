# Процесс работы с агентами — установка

Скилл общий для любого проекта: всё проектное берётся из самого проекта (README, CLAUDE.md, AGENTS.md, память, история git) и спрашивается у автора. Рядом с этим файлом:
- `orchestrator/` — скилл оркестратора целиком (с пулом имён и шаблонами задач и воркеров); копируется в проект. Его главный файл здесь называется `SKILL.template.md`, чтобы не считаться вторым скиллом, — при копировании переименовать в `SKILL.md`;
- `templates/` — шаблоны, нужные только при установке.

Этот скилл лежит в `.agents/skills/` и коммитится вместе с проектом: в нём он нужен, чтобы обновлять процесс (см. внизу), а чтобы завести процесс в другом проекте — скопировать туда папку `workflow-init` и запустить. Работу ведёт скилл `orchestrator`.

## 0. Разведка (ничего не меняя)
- Корень репозитория, текущая ветка, защищённые ветки (из CLAUDE.md, памяти, README; не ясно — спросить).
- Что уже есть: `.agents/`, `AGENTS.md`, `CLAUDE.md`, `.claude/` (skills, agents), `.gitignore` и что в нём.
- О проекте: назначение, стек, как собирать и проверять, языки интерфейса, ограничения автора.
- Что осталось от прошлой работы агентов (задачи, записки, отчёты, бэклог) — для переноса.
- Незакоммиченные изменения в `.gitignore`, `AGENTS.md`, `CLAUDE.md` — не затирать, только дописывать.

## 1. План автору — и ждать «да»
- дерево ниже: что создаётся, что попадёт в git, а что нет, какие строки добавятся в `.gitignore`;
- стартовый состав: по одному воркеру на роль (роли, которые проекту не нужны, — предложить пропустить), имена — первые из `orchestrator/names.md` или названные автором, с полом из пула (`{{PRONOUN}}`, `{{GENDER}}` в `AGENTS.md` воркера; у мужчины формы в тексте — мужские); специализацию разработчиков предложить по областям кода;
- раздел «Особенности проекта» для `workers/AGENTS.md`: защищённые ветки, правила коммита и push, ограничения;
- перенос: старые задачи → `.agents/tasks/` (статус по их тексту), записки → `CONTEXT.md` воркеров или `.agents/docs/`;
- что останется автору: коммит (только по его слову), правка ролей и пула имён.

## 2. Создание
```
AGENTS.md                           ← templates/root-AGENTS.md (есть — дописать раздел «Для агентов»)
CLAUDE.md                           ← строка @AGENTS.md (нет файла — создать)
.gitignore                          ← недостающие строки (ниже)
.claude/
  skills → ../.agents/skills        ссылка (см. ниже)
  agents/worker.md, reviewer.md     ← templates/claude-agents/ (только если таких нет)
.agents/
  docs/README.md                    ← templates/docs-README.md + разделы из разведки
  skills/orchestrator/              ← копия orchestrator/ (вся папка)
  workers/                          (не в git)
    AGENTS.md                       ← templates/workers-AGENTS.md: {{ROSTER}}, {{PROJECT}}
    orchestrator/CONTEXT.md         ← templates/orchestrator-CONTEXT.md
    <роль>/<имя>/AGENTS.md          ← orchestrator/templates/worker-AGENTS.md + секция из roles.md
    <роль>/<имя>/CONTEXT.md         ← orchestrator/templates/CONTEXT.md
    <роль>/<имя>/files/
  tasks/                            (не в git) задачи
  local/                            (не в git) входящие от автора, черновики
```

**`.gitignore`.** Нужны `.agents/workers/`, `.agents/tasks/`, `.agents/local/`. Каждую проверить `git check-ignore -q <путь>/x`; не игнорируется — дописать в конец файла под комментарием `# Агенты: рабочие файлы, не в git`. Существующие строки не трогать. Проверить, что `.agents/docs` и `.agents/skills` при этом **не** игнорируются (иначе — сказать автору).

**Скилл оркестратора.** Скопировать папку `orchestrator/` в `.agents/skills/orchestrator/`, `SKILL.template.md` → `SKILL.md`. Если там уже есть — показать автору разницу и спросить, заменять ли (в проектной копии могут быть его правки).

**Ссылки для Claude.** Claude Code ищет скиллы в `.claude/skills/`, Codex — в `.agents/skills/` (сам).
- `.claude/skills` нет → ссылка `.claude/skills` → `../.agents/skills`.
- `.claude/skills` — папка со своими скиллами → внутри ссылка на каждый скилл: `.claude/skills/<имя>` → `../../.agents/skills/<имя>`.
- Проверить: `ls -L .claude/skills/orchestrator/SKILL.md .claude/skills/workflow-init/SKILL.md`.

**Плейсхолдеры** `{{…}}` заполнить все, не оставлять. Пути в `AGENTS.md` воркеров — абсолютные (в worktree нет игнорируемых папок).

## 3. Перенос (если есть что)
По плану из шага 1: задача — по шаблону `orchestrator/templates/task.md`, id — время создания исходника (или текущее), в «Журнал» строка «перенесена из <путь>». Исходники не удалять — сказать автору, что можно убрать после проверки.

## 4. Проверка и отчёт
- `grep -rn '{{' .agents/workers AGENTS.md .agents/docs` — пусто.
- `git status --short` — в списке нет `.agents/workers`, `.agents/tasks`, `.agents/local`.
- Отчёт автору: дерево, состав (имя — роль — специализация), строки, добавленные в `.gitignore`, что перенесено, что закоммитить (обычно `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `.claude/`, `.agents/docs`, `.agents/skills`). Дальше — `/orchestrator`.

## Обновить процесс в проекте
Повторный запуск на проекте, где процесс уже есть: команду, задачи и память не трогать. Сравнить `.agents/skills/orchestrator/` с `orchestrator/` отсюда (`SKILL.md` ↔ `SKILL.template.md`) и `templates/workers-AGENTS.md` с `.agents/workers/AGENTS.md` (кроме «Состава» и «Особенностей проекта»); показать разницу, обновить по «да» автора.
