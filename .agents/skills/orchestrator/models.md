# Модели для воркеров: руководство оркестратору по оценкам и выбору

Обновлено: 2026-11-02 (по итогам Очередей 1 и 2 на эталонной задаче `promo-codes`, уровень `medium`, плюс базовые прогоны от 30.10).
Этот файл — самостоятельный источник приведённых правил и оценок: баллы и время отражают результаты указанных прогонов, а не гарантию для других задач. Доступность моделей, цены и квоты зависят от среды и меняются; перед назначением проверить их локально. Если подходящая модель недоступна, подобрать доступную с оператором и учитывать ограничения проекта.

## Как оркестратор выбирает модель по задаче

Бенчмарк `promo-codes` — одна задача на Python 3.12, 38 прогонов; разница в 1–2 балла может быть погрешностью. Сумма из 15 — оценки реализации, ревью и исправления, а не оценка тестирования. Оценки и время служат ориентиром, не гарантией на других задачах; результат каждого воркера проверяется независимо.

Определить роль, критичность и бюджет, затем выбрать доступного воркера из «Состава». **Оптимум** подходит для типовой разработки и используется по умолчанию; **Максимум качества** — для архитектуры, безопасности и критичной логики; **Экономный** — для мелких правок, простых скриптов или при исчерпании основных квот. Спорные выводы и масштабные изменения согласовать с оператором.

**Разово, вручную: быстрый расход квоты Antigravity.** `agy: claude-opus-5-5-medium` и `agy: claude-sonnet-5-5-medium` запускать только по прямому решению оператора, не в автоматических циклах. `claude: opus-5-5` работает в Claude Code со своей подпиской и относится к плану «Максимум качества»; это другая квота. OpenCode Go имеет общий лимит провайдера, бесплатные модели тоже ограничены; проверять доступность и балансировать провайдеров. Уровень рассуждения по умолчанию — `medium`.

## Команды запуска по харнесам (уровень `medium`)

| Харнес | Внутри Orca (`orca orchestration worker-start`) | Прямой CLI (вне Orca) |
|---|---|---|
| **codex** | `--agent codex --model <модель> --effort medium` | `codex exec -s workspace-write -C <wt> --add-dir <папка воркера> -m <модель> -c 'model_reasoning_effort="medium"' -o /tmp/<имя>-last.txt "<задание>" < /dev/null` (для ревью: `-s read-only`) |
| **agy** | `--agent antigravity --model <модель>-medium` | `cd <wt> && agy -p --mode auto --model <модель>-medium --add-dir <папка воркера> "<задание>"` |
| **opencode** | `--agent opencode --model <провайдер>/<модель>` | `cd <wt> && opencode run -m <провайдер>/<модель> --auto "<задание>"` |
| **src** | `--agent opencode --model sourcecraft/default` | `cd <wt> && src code -- run --dangerously-skip-permissions -m default "<задание>"` (или `src do "<задание>"`) |

## 1. Оркестратор (главный мозг: координация, запуск воркеров, реактивный контроль)

> **Критическое наблюдение по архитектуре харнесов:**  
> Для оркестратора **рантайм важнее чистой мощности модели**.
> - **`agy` (Antigravity) и `claude` (Claude Code):** имеют событийную шину реактивных пробуждений (`Reactive Wakeup`). Когда фоновый воркер завершает работу, рантайм автоматически доставляет событие главной сессии оркестратора, и тот моментально подхватывает управление без ручного пинга.
> - **`opencode`:** также поддерживает сессии, субагентов и статусные хуки.
> - **`codex` (OpenAI Codex CLI):** спроектирован как *одиночный синхронный исполнитель* (`unified_exec`). Он «засыпает» в ожидании ввода и не проверяет фон сам. Codex — первоклассный **разработчик**, но **непригоден как оркестратор**.

Рекомендуемые модели оркестратора:
1. `agy: gemini-3.8-flash-medium` — лучший баланс цена / скорость / ум (1M контекст), не жрёт квоту.
2. `claude: opus-5-5` *(в Claude Code)* — высший класс постановки задач и контроля качества.
3. `agy: gemini-4-argon-medium` — стабильная модель для чтения монорепозиториев (1M).
4. `opencode: opencode-go/minimax-m3` — экономный диспетчер задач.
