# Инициализация и миграция окружения оркестратора

Этот файл читается оркестратором только при отсутствии маркера `.agents/workers/.orchestrator-ready` или при явной команде оператора восстановить/настроить процесс («заведи процесс», «настрой окружение», «подготовь команду»).

## Маркер готовности

- Путь: `.agents/workers/.orchestrator-ready`
- Содержимое: `version=1`
- Маркер находится внутри игнорируемой папки `.agents/workers/`, не коммитится в git и отражает готовность локального рабочего места.
- Если маркер присутствует и содержит `version=1`, оркестратор не выполняет шаги инициализации и сразу начинает штатное ведение команды.

---

## Алгоритм инициализации

### Шаг 1. Проверка `.gitignore`
Убедиться, что рабочие файлы агентов исключены из репозитория:
```gitignore
# Агенты: рабочие файлы, не в git
.agents/workers/
.agents/tasks/
.agents/worktree/
.agents/local/
```
Проверить каждую папку через `git check-ignore -q <путь>/x`. Если не игнорируется — аккуратно дописать в конец `.gitignore`. Убедиться, что `.agents/docs/` и `.agents/skills/` при этом **не** игнорируются (они должны оставаться в git).

### Шаг 2. Создание структуры папок
Создать недостающие каталоги:
- `.agents/docs/` — знания о проекте для агентов (в git);
- `.agents/skills/orchestrator/` — единый скилл оркестратора (в git);
- `.agents/workers/` — состав, паспорта и память воркеров (не в git);
- `.agents/tasks/` — задачи (не в git);
- `.agents/tasks/done/` — архив проверенных задач;
- `.agents/tasks/cancelled/` — архив отменённых задач;
- `.agents/worktree/` — рабочие деревья активных задач (не в git);
- `.agents/local/` — черновики и заметки оператора (не в git).

### Шаг 3. Интеграция с Claude Code (`.claude/skills`)
Claude Code ищет скиллы в `.claude/skills/`.
- Если каталога `.claude/skills` нет: создать символическую ссылку `.claude/skills` → `../.agents/skills`.
- Если `.claude/skills` существует как отдельная папка: создать внутри ссылку `.claude/skills/orchestrator` → `../../.agents/skills/orchestrator`.
- Удалить устаревшую ссылку на `workflow-init`, если она была: `.claude/skills/workflow-init`.

### Шаг 4. Корневая документация проекта
- Если в корне проекта нет `AGENTS.md` — создать из `templates/root-AGENTS.md`. Если уже есть — проверить и при необходимости дописать раздел `## Для агентов`.
- Если нет `CLAUDE.md` — создать со строкой `@AGENTS.md`.
- Если нет `.agents/docs/README.md` — создать из `templates/docs-README.md`.

### Шаг 5. Команда воркеров (`.agents/workers/`)
- **Миграция действующего проекта:** если `.agents/workers/AGENTS.md` уже существует — **не перезаписывать состав и память!** Сохранить существующих воркеров, их специализацию и накопленный контекст.
- **Первичная установка в новом проекте:**
  1. Проверить доступные на машине CLI: `codex debug models`, `agy models`, `opencode models`, `src quota`.
  2. Сформировать стартовый состав по руководству `models.md`: назначить воркеров с проверенными навыками (5/5 для ядра, 4/5 бесплатные для простых задач), используя имена из `names.md` с указанием пола.
  3. Заполнить `templates/workers-AGENTS.md` и сохранить в `.agents/workers/AGENTS.md`.
  4. Для каждого штатного воркера создать каталог `.agents/workers/<роль>/<имя>/`:
     - `AGENTS.md` (из `templates/worker-AGENTS.md` с подстановкой секции роли из `roles.md`);
     - `CONTEXT.md` (из `templates/CONTEXT.md`);
     - пустую папку `files/`.
  5. Убедиться в наличии `.agents/workers/orchestrator/CONTEXT.md` (создать из `templates/orchestrator-CONTEXT.md`, если отсутствует).
  6. Убедиться в наличии реестров архивов: `.agents/tasks/done/README.md` и `.agents/tasks/cancelled/README.md` (создать с базовым заголовком реестра, если отсутствуют).

### Шаг 6. Валидация и фиксация маркера
Перед записью маркера убедиться, что:
1. `.agents/workers/AGENTS.md` существует и содержит непустой состав команды;
2. `.agents/workers/orchestrator/CONTEXT.md` существует;
3. Каталоги `tasks/`, `docs/`, `workers/` доступны для чтения и записи.

Если всё в порядке — записать файл `.agents/workers/.orchestrator-ready`:
```
version=1
```
Если обнаружена ошибка — маркер не ставить, вывести ошибку оператору.

### Шаг 7. Переход к работе
Сообщить оператору об успешной подготовке среды и сразу же в этой же сессии перейти к штатному старту оркестратора (сверка ветки, рабочих деревьев и вывод доски).
