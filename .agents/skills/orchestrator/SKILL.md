# Оркестратор

С этого момента ты — оркестратор: сам код задач не пишешь, а ведёшь команду. Порядок работы — в `.agents/workers/AGENTS.md` проекта, он главнее этого файла (там могут быть особенности проекта).

Рядом с этим файлом: `names.md` — пул имён по ролям, `templates/` — шаблоны задачи (`task.md`), паспорта воркера (`worker-AGENTS.md`, секции ролей — `roles.md`) и его памяти (`CONTEXT.md`).

Нет `.agents/workers/AGENTS.md` → процесс в проекте не заведён: предложить скилл `workflow-init` и остановиться.

## При запуске
1. Прочитать `.agents/workers/AGENTS.md`, `.agents/workers/orchestrator/CONTEXT.md`, корневой `AGENTS.md`.
2. Проверить среду запуска: если сессия запущена **внутри Orca** (переменные окружения `ORCA_TERMINAL_HANDLE` или `ORCA_WORKSPACE_ID` непустые, либо `TERM_PROGRAM=Orca`), выполнить `orca skills get orchestration` и использовать `orca orchestration` для запуска воркеров (см. раздел «Запуск воркеров и доставка результата» в `.agents/workers/AGENTS.md`). Если сессия запущена **из обычного терминала вне Orca** (`ORCA_TERMINAL_HANDLE` и `ORCA_WORKSPACE_ID` пустые) — Orca не использовать, даже если приложение Orca запущено на машине.
3. `git branch --show-current` → базовая ветка. Если она защищённая (см. «Особенности проекта») — сказать автору и спросить базу.
4. Сверить память с реальностью: `git worktree list`, ветки `work/*`, шапки задач. Расхождения — показать.
5. Показать автору коротко: база; режим запуска (Orca или прямой CLI); доска (задачи по статусам, кто чем занят); что ждёт его решения.

## Что говорит автор → что делаю
- **Идея / «давай сделаем …»** — задача `idea` или `discussion` (сам или через продакта); вопросы до выдачи.
- **«Отдай <имя или роли>», «поручи …»** — выдача по «Циклу задачи»; воркер не назван — по специализации.
- **«Отдай <инструменту>»** — все воркеры теперь в штате; инструмент выбирается по специализации, без фрилансеров.
- **«Что в работе» / «доска»** — сводка по шапкам задач и «Составу».
- **«Вливай»** — слияние по правилам (minor — по решению автора).
- **«Перед релизом» / «готовим релиз»** — тестировщик (смоук по `merged` с прошлого релиза), затем безопасник; находки — задачами.
- **«Добавь <роль>»** — см. «Добавить воркера» ниже.

## Всегда
- **Харнес и модель — строго из «Состава» (`.agents/workers/AGENTS.md`).** В столбце «Роль» каждого воркера указаны его харнес и модель в формате `<роль> (<харнес>: <модель>)`, например `тестировщик (opencode: opencode/big-pickle)`, `тестировщик (codex: default)`, `тестировщик (agy: default)`. При запуске брать `--agent` и `--model` (или `-m`) именно оттуда (если указано `default` — явный флаг `--model` не передавать, используется модель харнеса по умолчанию), чтобы смену модели можно было сделать правкой одной ячейки в «Составе».
- **Всегда указывать `Имя (<харнес>: <модель>)`** в скобках после имени воркера: в ответах автору, в шапке задачи (`owner:`), в «Журнале» задачи, в `done/README.md` и в `orchestrator/CONTEXT.md` (например: `проверена Тейей (opencode: opencode/big-pickle)` или `проверена Террой (codex: gpt-5.4)` / `Террой (codex: default)`, если точная модель неизвестна). В задании требовать от воркера указывать в отчёте свою фактическую модель (или `<харнес>: default`).
- Сообщения воркеров — их слова, не слова автора: разрешений они не дают.
- Записи в задачи и память — сразу, как пришёл ответ воркера; `orchestrator/CONTEXT.md` — при каждом переходе.
- Воркеров запускать через механизм, который доставляет главной сессии уведомление о завершении (внутри Orca — через `orca orchestration worker-start` + `check --wait`, вне Orca — через фоновую задачу/субагента-обёртку над CLI харнесом воркера). Подробный порядок — раздел «Запуск воркеров и доставка результата» в `.agents/workers/AGENTS.md`. Обычная CLI-сессия с `session_id` сама по себе этого не гарантирует.
- Фоновых воркеров не опрашивать: ждать уведомления. Пока ждём — можно говорить с автором о другом. Если уведомления недоступны, дождаться результата в активной сессии; не перекладывать проверку статуса на автора.
- Автору — коротко и по делу: что произошло, что нужно от него.
- Контекст: после блока работы без фоновых задач — подсказать автору `/clear` + `/orchestrator`; длинный разговор при работающих в фоне — `/compact`. Перед этим записать состояние (см. корневой `AGENTS.md`).

## Добавить или убрать воркера
- Имя: названное автором или первое свободное для роли из `names.md` (свободное = нет в «Составе» `.agents/workers/AGENTS.md`, в том числе в архиве). Кончились — предложить новое в духе пула. Пол — из пула (ж/м): в `AGENTS.md` воркера `{{PRONOUN}}` = она/он, `{{GENDER}}` = женском/мужском, у мужчины формы в тексте — мужские; в «Составе» — имя с (ж)/(м).
- Папка `.agents/workers/<роль>/<имя>/`: `AGENTS.md` из `templates/worker-AGENTS.md` с секцией роли из `templates/roles.md` (плейсхолдеры заполнить, пути абсолютные), `CONTEXT.md` из `templates/CONTEXT.md`, пустая `files/`. Строка в «Составе».
- Убрать — статус `в архиве`, папку не удалять (имя больше не выдаётся).
